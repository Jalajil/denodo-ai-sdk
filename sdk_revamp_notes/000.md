This step finds views relevant to your question and gathers their metadata, including column details and associations, along with sample values to help the SDK generate a query. By default, embeddings_token_limit=0 during metadata indexing stores the whole view metadata as one embedding document. Set embeddings_token_limit to a positive token count during metadata synchronization to split views whose metadata exceeds that limit into multiple embedding documents. Each chunk still carries the full view definition in view_json. Search metadata within authorized IDs and database/tag filters, deduplicate matches from the same view, then append associated views and use_views within the total cap. This means the combined list cannot exceed vector_search_total_limit, which defaults to 20 views in total, including initial matches, associated views and explicitly named views. If chunk matches leave fewer than k distinct views, the SDK can search up to two more times, excluding views already found. It reuses the question embedding, makes no extra LLM call, and may still return fewer than k views. Row-restricted views skip stored samples; restricted sample columns are removed. expand_set_views=false filters the result to use_views after retrieval, so it does not eliminate the embedding/search work.
