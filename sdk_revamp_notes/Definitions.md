Associations: How rows of two views are related. 
Example: Customers.id  ←→  Sales.cust_id

- Samples: By default the SDK retrieves 100 random rows per view and then embed them and for each query from the user, a semantic search would run to return up to 3 samples for each column to the agent.   
	The following example shows how samples are provided to the agent and they are per column:
	- order_reference (text) sample values: ORD-001, ORD-002, ORD-003
	- status (text) sample values: pending, approved, rejected
	- country_code (text) sample values: SA, IN, US

Data Marketplace: Acts as the controlled gateway between the SDK and Denodo:
- It provides metadata about available views, fields, descriptions, associations, and samples.
- It checks which views the current user is permitted to access.
- It receives and executes the VQL query generated by the AI SDK.
- It returns the query results.

Tags: Are put on views to distinguish one another*.

getMetadata: Extracts Denodo metadata such as views, fields, descriptions, associations, and optionally samples. It then filters them (using tags to select or exclude certain views) and formats them (such as JSON). If `insert=true`, it also embeds the formatted metadata and inserts the embeddings into the vector store.

**`chatbot_config.env`** configures the sample user interface and conversation agent. It includes things such as:

- Chatbot model
- Chat history database
- UI behavior
- Address of the AI SDK, such as `AI_SDK_URL=http://localhost:8008`

**`sdk_config.env`** configures the actual AI SDK backend. It includes:

- API host and port
- Data Marketplace URL
- LLM used for VQL generation
- Embedding model
- Vector-store connection
- Query row limits
- DeepQuery settings
- MCP server settings
- Access controls

This separation is needed because the AI SDK can run **without the sample chatbot**. Another application can call its REST endpoints or MCP tools directly.

- ### The question is unclear
	“Show sales” might mean order count or money received. ==With ambiguity checks enabled==, the SDK can ask for clarification before generating a query.

- ### The query fails
	An error message can help ==an additional model call revise the query when the fixer is enabled==. The SDK tries again within a bounded repair flow.

- ### The query returns empty
	Return empty by default. If `enable_query_reviewer=true`, ask the reviewer to keep the query or rewrite it.
