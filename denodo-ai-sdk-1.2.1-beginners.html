What are we connecting?

Denodo lets applications query data from different systems through one access layer. This is called data virtualization: data can be presented together without first copying everything into one new database.

The AI SDK, short for artificial intelligence software development kit, is software developers use to connect AI applications to that layer. It coordinates finding the right data descriptions, asking an AI model to write a query, and running it.

Data Marketplace helps people discover and understand available data. It also has an API, an interface that programs call to request information or actions. This SDK uses that interface to retrieve descriptions, check access, and submit queries. You do not need to browse its website for each question.

Keep these jobs separate: the AI model proposes the query. Denodo executes it. The returned data supplies the numbers in the answer.

First, meet the data

A view is a named, table-shaped way to access data in Denodo. Think of a spreadsheet with named columns. A view can combine or transform information from other sources; it need not be a separately stored copy.

Data: actual values
Example view: sales.orders
order_idregionamount

102East90
103West80
104East60

One row = one order.
A column describes one part of that order, such as its amount. A cell is one value, such as 120.

For this exercise, these four orders are the complete dataset. All amounts use the same imaginary currency.
Schema: the structure
View name
sales.orders, orders in a database named sales.
Columns
order_id, region, amount.
Data types
Order ID is a whole number, region is text, amount is a decimal number.
Meaning
The amount column is the value of one order.

Schema means the data's structure: what views and columns exist and what kinds of values they contain.

Metadata is information about data. It includes the schema plus useful descriptions and relationships. “One row is one order” is metadata. The value 120 is data. Knowing what one row represents is sometimes called granularity.

What are sample rows?

They are a small selection of real records used as examples. Seeing West and East can help the model understand how region names are written.

Possible sample: just two orders

101 · West · 120
102 · East · 90

These examples do not contain all four orders.

Samples are optional and may be restricted by access rules. Stored samples can also become old. The SDK needs query results to answer the total-amount question.

Why descriptions matter

“Amount” might mean before tax, after tax, or after refunds. A column name alone may leave the business meaning unclear.

A useful description

“Amount of each completed order, after discounts, before tax.”

That tells the model which interpretation to use when this description is supplied in its context.

What if the information is in two views?

An association describes how views relate. For example, an order's region_id may match an ID in a regions view. A join is the query operation that combines matching rows to attach the region name. The relationship helps the model write the join correctly.

Before questions: build a searchable guidebook

The SDK first needs a way to find relevant metadata. Imagine making a searchable guidebook of the available views. This preparation is called metadata synchronization: collecting and updating the descriptions the SDK can search.

1. Read descriptions

Ask Data Marketplace for the selected views, their columns, descriptions, and relationships.

2. Make searchable numbers

An embedding model turns the text into lists of numbers that help compare its meaning.

→

3. Save the index

Store descriptions and their number representations in a vector store. Optional samples are indexed separately.

An embedding is that numerical representation of meaning. A vector store is a database designed to search those representations. This lets “order totals” find a description about “sales amounts” even when the wording differs. Matches can still be imperfect.

What is being prepared? A search index of context for the AI. Optional sample data may be copied into it, but it is not a complete replacement for the underlying business data.
What needs to be set up first?

A developer configures access to Denodo and its Data Marketplace, an AI text model, an embedding model, and a vector store. These are separate roles, even if one provider supplies several. Configuration means supplying settings such as service addresses and model choices. Credentials prove who is making a request.

The SDK exposes a metadata operation named /getMetadata. An endpoint is the address of a specific API operation. The caller selects a database or a tag, a label used to group views, and must have permission to synchronize metadata. Refresh this index when the relevant definitions change.

Now follow the question

This shows the standard data-question path. Each stage has a different job. Open the extra explanations when you want more detail.

  1. Send the question with its boundaries

    Your application sends the question to the SDK. It also identifies the user and can specify which database to search. That boundary is called the scope. Permissions describe what that user is allowed to access.

    Input

    “What is the total order amount for each region?”

    →
    Request

    Question + user identity + sales database scope.

  2. Find the relevant data descriptions

    The SDK searches the guidebook by meaning and checks access. It retrieves context, meaning the information given to the model for this task. Here, that includes the orders view and its column descriptions.

    Search among descriptions

    Orders · Products · Employees

    →
    Relevant context

    Orders: region is text; amount is a number; one row represents one order.

    Where do samples and permissions fit?

    The SDK can add relevant stored sample values and related views. In this release, a view with row restrictions does not contribute stored samples to the request; restricted sample columns are removed. If there are no usable views, the request stops.

    Retrieval-augmented generation (RAG) means finding relevant information and giving it to a model before asking it to generate an output. In this path, much of that information describes the data to query.

  3. Ask the model what it needs

    A large language model (LLM) is an AI model that processes and generates text. The first model call in this data path selects relevant views and query capabilities. For this question, it needs orders and a way to add amounts together.

    Question + candidate descriptions

    Total amount for each region.

    →
    Selection

    Use the orders view. Group by region and calculate totals.

    This is an illustrated selection, not a recorded response from a model.

  4. Give the model a clear writing brief

    A prompt is the set of instructions and context sent to a model. The SDK assembles the question, selected schema, relevant samples, and query-language rules. A second model call generates the query.

    Illustrated prompt ingredients

    Task: total order amount by region.
    Available fields: region and amount in sales.orders.
    Meaning: one row is one order.
    Rules: use known names and Denodo's query language.

    SQL is a language for asking structured questions of data. VQL, Denodo's Virtual Query Language, is the query language used here. The SDK returns the generated query in a field called sql_query.

    SELECT region, SUM(amount) AS total_amount
FROM sales.orders
GROUP BY region;
    Read the query in everyday language
    Query partWhat it asks
    FROM sales.ordersUse the orders view.
    GROUP BY regionPut orders with the same region into a group.
    SUM(amount)Add the amounts inside each group.
    AS total_amountName the output column total_amount.
    Does writing a query mean it is correct?

    No. The SDK extracts the generated query text, then attempts execution. A query can fail to run, or run successfully while answering the wrong business question. Clear metadata and checking the result both matter.

  5. Run the query through Denodo

    Execution means actually running those instructions. The SDK submits the VQL through Data Marketplace using the user's credentials. Denodo evaluates the query against the data available to that user.

    Orders being combined

    West: 120 + 80 = 200
    East: 90 + 60 = 150

    The calculation uses all four orders in our example, not just the two sample rows.
    Result: calculated totals
    West
    200East
    150

  6. Return the result, then explain it

    The SDK returns the query and the result rows. With prose generation enabled, a model also turns those rows into a readable answer.

    Illustrative answer based on the result

    West has a total order amount of 200, and East has 150.

    A response is the bundle returned to the application. It can include the answer, query text, rows, timing, and model-usage information. A row limit caps returned records; a prose answer can only summarize the result it receives.

    Does the model see business data?

    Relevant descriptions and permitted samples can be included during query generation. When the model writes the final explanation, it receives a serialized result, meaning rows converted into text the model can read. Which service receives this information depends on the model configuration.

The distinction to remember: descriptions help choose and write the query. Sample rows illustrate values. Executed query results provide the answer data.

When the answer is not straightforward

The question is unclear

“Show sales” might mean order count or money received. With ambiguity checks enabled, the SDK can ask for clarification before generating a query.

The query fails

An error message can help an additional model call revise the query when the fixer is enabled. The SDK tries again within a bounded repair flow.

Next: a revised query or an error.

The query returns no rows

This can be a valid outcome. A separate, optional reviewer can reconsider an empty result. In the standard endpoint, that reviewer is off by default.

Next: an empty result or review.
Technical detail: how many retries?

The 1.2.1 resolver limits its fix/review loop to two iterations. A special rewrite for a known query issue can consume one fixer attempt when it leads into that flow. A successful execution still does not establish that the business interpretation was correct.

Other paths you will see in the original guide

You can understand the basic journey before learning these extensions.

A question about data descriptions

“Which view contains order amounts?” is a metadata question. It can be answered from descriptions without executing a data query. “How much did we sell?” needs data results.

A chatbot or agent chooses tools

An agent is software that uses a model to choose actions. A tool is an action it can request, such as searching descriptions or asking the SDK a data question. The sample chatbot can call SDK tools and compose the final wording itself.

MCP, Model Context Protocol, is a shared interface for connecting AI applications to tools. It is another way to make SDK operations available to an application.

DeepQuery handles a bigger investigation

“Why did sales fall?” can need several questions, comparisons, and intermediate results. DeepQuery is the SDK's multi-step analysis path. It can plan an investigation and call tools repeatedly. Report generation is a separate stage that turns analysis information into an HTML report.

Recognizing API settings

/answerQuestion names an endpoint. mode="data" selects the data-question path. verbose=true requests a prose explanation. plot=true requests a chart. enable_query_fixer controls repair of failed queries.

Streaming means delivering output progressively. Tokens are the small text units models process; usage counts help track cost and limits. Latency means how long the operation takes.

Check your understanding

Could the SDK total sales using only the two sample rows?

It could add those two numbers, but that would not answer our full question. West's missing order is 80 and East's is 60. The full result is West 200 and East 150. Samples help describe the values; the query must operate on the relevant data to obtain the totals.
