03 / Row-limit boundaries

“100 rows” can mean different things.

Execution, model context and agent evidence are different boundaries. One declared chatbot setting is not enforced by the current tool path.

100

Denodo → SDK

vql_execute_rows_limit

Default request execution rows. Valid range: 1 to the environment ceiling, whose fallback is 10,000.

100

SDK → answer LLM

LLM_RESPONSE_ROWS_LIMIT

Environment fallback. Produces llm / llm_csv alongside full / full_csv in the result bundle.

15

Declared chatbot setting

CHATBOT_LLM_RESPONSE_ROWS_LIMIT

Config fallback, overridable per profile. Current data tool formatting uses SDK llm_csv directly and does not enforce a separate 15-row cap.

10

Tool → analysis agent

default_rows

DeepQuery evidence cap and prompt guidance. The tool can specify another row count; nested query execution retains its own defaults.

There is also examples_per_table=100 during indexing and vector_search_sample_data_k=3 during retrieval. Those are schema-grounding samples, not query result rows.

Where the pipeline can end early
Authorization / scope
No allowed views, no indexed matches or missing feature access. Resolve permissions or synchronize the relevant metadata.
Clarification
Ambiguity checking finds missing intent. The response asks for clarification before VQL generation.
No query generated
The generator returns empty/None VQL. NO_QUERY returns an explanation without execution.
Execution error
Fixer can rewrite and retry, give up, or exhaust its two-iteration budget. Disabled fixer returns the failure.
Zero rows
Valid empty result by default. Optional reviewer may keep it or rewrite the query and execute again.
Analysis loop exhausted
The agent tries to produce a partial final answer. A loop cap is not a guarantee of a complete investigation.


Two source details that affect nested agents: DeepQuery database calls create a fresh answerQuestionRequest with server-default model/retrieval settings; outer overrides are not universally forwarded. The report graph helper also does not forward analysis database/tag scope, so graph queries use its helper defaults, while Denodo authentication remains in effect. Review these boundaries when configuring a scoped assistant.

Custom-agent YAML: what can be configured
name and id are required. Name length: 1-60; ID: lowercase slug up to 255 characters. Top-level unknown properties are disallowed. Access lists use allowed_users and allowed_roles; either match grants profile access when both are present.
settings supports feature flags, chatbot LLM settings, SDK base/thinking LLM settings, response-row limits, report file limits, database/tag scope, knowledge bases, system-skill selection, and separate chatbot/SDK custom instructions. Known nested schema fields are documented in the source; not every nested object sets additionalProperties=false.
knowledge_bases lists collection names that must exist before the profile is usable. skills omitted allows all applicable system skills; an empty list allows none of them, while personal skills still apply. The runtime config supplies defaults, not the YAML schema itself.
